## 1. 개념 소개

**하네스 엔지니어링**은 AI 에이전트(Claude)의 행동을 체계적으로 설계하고 운영하는 방법론입니다.

자동차 공장의 **조립 라인**을 생각하면 이해하기 쉽습니다:

```
자동차 조립 라인           하네스 엔지니어링
───────────────           ──────────────────
각 공정 담당 작업자   →    페르소나 (역할 분리)
정해진 조립 순서      →    워크플로 (단계 분리)
공정별 체크리스트     →    에이전트 파일 (행동 규칙)
불량품 리턴 규칙      →    루프 규칙 (품질 보장)
```

### 왜 필요한가?

| 문제 상황 | 하네스 엔지니어링 해결책 |
|---|---|
| AI가 매번 다른 스타일로 답변 | 에이전트 파일로 행동 규칙 고정 |
| 역할 바꿀 때 모델 수동 전환 필요 | 훅(Hook)으로 자동 전환 |
| 복잡한 작업을 한번에 처리하다 실수 | 단계별 분리로 품질 보장 |
| 이전 대화 맥락이 섞여 혼란 | 페르소나 격리로 컨텍스트 오염 방지 |

## 2. 동작 원리

슬래시 커맨드를 입력하면 아래 흐름으로 동작합니다:

```
사용자 입력 (예: /se:plan)
        │
        ▼
┌─────────────────────┐
│  UserPromptSubmit 훅 │  ← 자동으로 적절한 모델로 전환
│  (settings.json)    │     예) claude-opus-4-7 로 전환
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│   페르소나 활성화    │  ← 역할 로드: 보안 엔지니어 / 학부생 등
│   (에이전트 파일)   │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│     단계 실행       │  ← 계획 → 비판 → 확정 → 실행 → 검토 → 문서화
│   (워크플로 단계)   │
└──────────┬──────────┘
           │
           ▼
     산출물 저장 (_harness/ 폴더)
```

### 보안 엔지니어 워크플로 예시

```
[/se:plan] → [/se:critique] → (불충분하면 반복)
                                      │
                              충분히 좋아지면
                                      │
                                      ▼
                            [/se:confirm] → [/se:execute] → [/se:review] → [/se:doc]
```

## 3. 구성 요소 예시

### 페르소나 종류

| 페르소나 | 커맨드 | 역할 | 사용 모델 |
|---|---|---|---|
| 보안 엔지니어 | `/se:plan` ~ `/se:doc` | 보안 프로젝트 계획·실행·문서화 | Opus 4.7 / Sonnet 4.6 / Haiku 4.5 |
| 학부생(교수님) | `/teacher:ask` | 개념 질문과 쉬운 설명 | Sonnet 4.6 |
| 학부생(문서화) | `/teacher:doc` | 학습 내용 정리 | Sonnet 4.6 |

### 파일 구조

```
_harness/
├── history.md                        # 전체 프로젝트 이력
├── permissions.md                    # MCP/권한 목록
├── security_engineer/
│   ├── 01_plan.md                    # 계획 에이전트 설명서
│   ├── 02_critique.md                # 비판 에이전트 설명서
│   ├── plan.md                       # 확정된 최종 계획
│   └── docs/                         # 보안 문서 산출물
└── student/
    ├── 01_ask.md                     # 질문 에이전트 설명서
    ├── 02_document.md                # 문서화 에이전트 설명서
    └── docs/                         # 학습 노트 모음 (여기!)
```

## 4. 핵심 정리

| 키워드 | 설명 |
|---|---|
| **페르소나(Persona)** | AI에게 부여한 역할. 역할마다 행동 방식이 완전히 분리됨 |
| **워크플로(Workflow)** | 단계별 작업 흐름. 순서를 어기면 품질이 떨어짐 |
| **훅(Hook)** | 특정 이벤트(슬래시 커맨드 입력) 시 자동 실행되는 스크립트 |
| **에이전트 파일** | 각 단계의 역할·행동 규칙을 담은 마크다운 설명서 |
| **루프 규칙** | 계획-비판을 충분히 좋아질 때까지 반복하는 품질 보장 메커니즘 |
| **페르소나 격리** | 다른 페르소나의 이전 맥락을 가져오지 않는 원칙 |
| **SBOM** | 소프트웨어 구성 요소 목록. 보안 실행 단계에서 생성 |

## 5. 더 알아보기

### 연관 키워드
- **프롬프트 엔지니어링**: AI에게 좋은 지시문을 작성하는 기술. 하네스의 기반
- **에이전트(Agent)**: 목표를 위해 스스로 행동을 결정하는 AI 프로그램
- **훅(Hook)**: 이벤트 기반 자동 실행 스크립트 (`settings.json` 에 설정)
- **멀티 에이전트 시스템**: 여러 AI 에이전트가 협력하는 구조

### 더 공부하면 좋은 질문들
- 훅(Hook)은 `settings.json` 에 실제로 어떻게 설정하나요?
- 페르소나 격리가 왜 중요한가요? 컨텍스트가 섞이면 무슨 일이 생기나요?
- 계획-비판 루프에서 "충분히 좋다"는 기준은 어떻게 정하나요?
- 하네스 엔지니어링과 일반 프롬프트 엔지니어링의 차이는?
